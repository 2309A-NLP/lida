# 优化建议 - 未来可实施方向

## 建议 1：安装 FlagEmbedding 启用向量检索（高优先级）

### 问题
当前使用 jieba + BM25 关键词匹配，缺乏语义理解能力，同义词、近义词、相关概念无法被有效召回。

### 方案
安装 FlagEmbedding 及其依赖，使用 BGE (BAAI/bge-small-zh-v1.5) 或类似模型生成文本嵌入向量。

### 实施步骤
```bash
pip install FlagEmbedding transformers torch
```

### 预期效果
- 检索准确率提升 30-50%
- 支持语义搜索，不再依赖关键词精确匹配
- 可配合 Milvus 实现高效向量检索

### 注意事项
- 模型加载需 500MB-1GB 内存
- 首次加载较慢，建议使用单例模式缓存模型
- 如无 GPU，CPU 推理速度可接受（小批量场景）

## 建议 2：配置 Milvus 向量数据库（高优先级）

### 问题
当前无向量数据库，知识库检索全部在内存中进行，随着文档量增长性能下降明显。

### 方案
部署 Milvus 向量数据库（可使用 Milvus Lite 或 Docker 部署），存储文档嵌入向量。

### 实施步骤
1. 安装 pymilvus：`pip install pymilvus`
2. 编写 Milvus 集合管理代码
3. 在知识库初始化时将文档向量写入 Milvus
4. 检索时先查询 Milvus 获取相似文档，再送入 LLM

### 预期效果
- 支持百万级文档的高效检索
- 检索延迟稳定在 10-50ms
- 支持向量混合检索（向量 + 关键词加权）

### 替代方案
- 若不想部署独立数据库，可使用 FAISS（本地向量索引，无持久化）
- 或使用 ChromaDB（轻量级嵌入式向量数据库）

## 建议 3：精简中文分词策略（中优先级）

### 问题
当前使用 jieba 全模式分词，可能产生过多冗余词汇，影响 BM25 相关性打分。

### 方案
1. 切换为 jieba 精确模式（cut_all=False）
2. 添加自定义词典（领域专有名词）
3. 过滤停用词
4. 可选：使用 HanLP 或 LAC（百度词法分析）替代 jieba

### 示例代码
```python
import jieba
jieba.load_userdict("dict/custom_words.txt")

def tokenize(text: str) -> list[str]:
    words = jieba.lcut(text)  # 精确模式
    stopwords = load_stopwords("dict/stopwords.txt")
    return [w for w in words if w not in stopwords and len(w) > 1]
```

### 预期效果
- 减少噪声词汇，提升 BM25 相关性打分质量
- 提高专有名词的识别准确率

## 建议 4：增加 Redis 缓存知识库检索结果（中优先级）

### 问题
相同或相似的查询反复触发知识库检索，每次都需要完整的 BM25 计算或向量检索。

### 方案
引入 Redis 缓存检索结果，设置 TTL 过期策略。

### 实施步骤
1. 安装 redis-py：`pip install redis`
2. 部署 Redis（Docker 或本地安装）
3. 检索前先查询缓存，命中则直接返回
4. 缓存 key 设计：`knowledge:query:{md5(query)}`

### 预期效果
- 重复查询延迟从 ~200ms 降低至 < 5ms
- 减少后端计算压力
- 热点查询自动加速

### 缓存策略
```python
import hashlib
import json

def get_cache_key(query: str) -> str:
    return f"knowledge:query:{hashlib.md5(query.encode()).hexdigest()}"

def search_with_cache(query: str, ttl: int = 3600):
    cache_key = get_cache_key(query)
    cached = redis_client.get(cache_key)
    if cached:
        return json.loads(cached)
    result = knowledge_service.search(query)
    redis_client.setex(cache_key, ttl, json.dumps(result))
    return result
```

## 建议 5：DeepSeek API 流式响应（高优先级）

### 问题
当前请求 DeepSeek API 使用非流式模式，用户需等待完整回复生成后才能看到内容。

### 方案
启用流式响应（stream=True），将 LLM 输出逐 token 返回给前端。

### 实施步骤
1. 后端：使用 `requests` 的 stream 参数或 `httpx` 的流式接口
2. 后端：使用 FastAPI 的 `StreamingResponse` 返回 SSE (Server-Sent Events)
3. 前端：使用 `EventSource` 或 `fetch + ReadableStream` 接收流式数据

### 后端示例
```python
from fastapi.responses import StreamingResponse
import httpx

async def stream_chat(query: str, context: str):
    async with httpx.AsyncClient(timeout=60) as client:
        async with client.stream(
            "POST",
            "https://api.deepseek.com/chat/completions",
            headers={"Authorization": f"Bearer {api_key}"},
            json={"model": "deepseek-chat", "messages": [...], "stream": True}
        ) as response:
            async for line in response.aiter_lines():
                if line.startswith("data: "):
                    yield line[6:] + "\n\n"

@app.post("/chat/stream")
async def chat_stream(request: ChatRequest):
    return StreamingResponse(
        stream_chat(request.query, request.context),
        media_type="text/event-stream"
    )
```

### 预期效果
- 用户感知延迟大幅降低（从数秒到数百毫秒的首 token 时间）
- 用户体验显著提升（所见即所得）

## 建议 6：前端打字机效果（中优先级）

### 问题
即使后端实现流式响应，前端如果一次性渲染所有内容，用户体验的提升有限。

### 方案
前端实现打字机（逐字显示）效果，配合流式响应使用。

### 前端示例（JavaScript）
```javascript
async function streamChat(query) {
    const response = await fetch('/chat/stream', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ query })
    });
    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    let text = '';

    while (true) {
        const { done, value } = await reader.read();
        if (done) break;
        text += decoder.decode(value, { stream: true });
        // 逐字显示
        displayText(text);
    }
}
```

### 预期效果
- 更自然的对话体验
- 让用户感觉 AI "正在思考并生成回答"
- 与流式响应配合产生最佳效果

## 建议 7：数据库连接池（低优先级）

### 问题
当前数据库操作每次创建新连接，高并发场景下性能不佳。

### 方案
使用 SQLAlchemy 连接池或自定义连接池管理。

### 示例
```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine(
    "sqlite:///./data/app.db",
    pool_size=10,
    max_overflow=20,
    pool_pre_ping=True
)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

# 依赖注入
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

### 预期效果
- 高并发场景下数据库响应时间降低 50-80%
- 避免重复创建/销毁连接的开销
