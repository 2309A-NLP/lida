## 二、RAGFlow检索架构分析

### 2.1 系统架构
RAGFlow的检索流程包含以下核心模块：

```
用户查询 → 查询理解 → 向量检索 → 重排序 → LLM生成 → 答案
```

### 2.2 核心模块说明

| 模块 | 功能 | 技术实现 |
|------|------|----------|
| Embedding | 文本向量化 | bge-m3 (本地部署) |
| Retrieval | 向量检索 | Elasticsearch |
| Rerank | 结果重排序 | bge-reranker-base (本地部署) |
| LLM | 答案生成 | mimo-v2.5 (小米API) |
| VLM | 图像理解 | mimo-v2-omni (小米API) |

### 2.3 检索流程

1. **查询理解**：解析用户问题，提取关键词
2. **向量检索**：将问题转换为向量，在Elasticsearch中检索相似文档块
3. **重排序**：使用Rerank模型对检索结果进行精细化排序
4. **上下文构建**：选取Top-N个最相关的文档块作为上下文
5. **答案生成**：LLM根据上下文生成答案

## 三、问题诊断

### 3.1 故障分析

#### 故障1：检索无关
当用户提问"编号13的部件相对于编号12..."时，系统可能仅通过"部件"、"编号"等泛文本关键词检索，返回大量提及部件编号但不含图3的文本块。

#### 故障2：图文割裂
即使检索到了包含图3的页面，系统也可能无法将"编号13"、"位置关系"等查询词与图纸的图像特征进行关联。

### 3.2 根本原因
1. **图3为纯图片页面**：第11页是纯图片，没有文字内容，OCR无法提取有效文本
2. **缺乏图文关联**：检索系统无法将文本查询与图片内容关联
3. **分块策略问题**：图片页面无法生成有效的文本分块

## 四、优化方案

### 4.1 方案设计

#### 方案1：VLM图像描述
使用视觉语言模型(VLM)对图3进行分析，生成详细的部件描述文档，补充到知识库中。

#### 方案2：检索参数优化
调整检索参数，平衡准确率和响应时间：
- top_k: 3（初始检索分块数）
- top_n: 1（Rerank后保留数）
- similarity_threshold: 0.1
- vector_similarity_weight: 0.3

#### 方案3：Rerank重排序
集成bge-reranker-base模型，对检索结果进行精细化排序，优先选出最匹配图文语义的片段。

### 4.2 实施步骤

1. **VLM分析图3**
   - 导出第11页图片
   - 使用mimo-v2-omni分析部件位置关系
   - 生成结构化的部件描述文档

2. **知识库补充**
   - 将图3描述文档上传到知识库
   - 确保文档被正确解析和分块

3. **参数优化**
   - 调整top_k、top_n参数
   - 优化相似度阈值和向量权重
