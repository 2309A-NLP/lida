> 项目路径: `D:\Agent工单\Agent工单1`

## 一、项目背景

### 1.1 开发目标

开发一个基于大语言模型的家庭记账本Agent，用户通过自然语言即可完成记账、查询、删除等操作，无需手动填写表格。

### 1.2 核心需求

- **LLM驱动**: 必须使用大模型理解自然语言，不能纯正则匹配（规则引擎无法理解"买了...又买了..."等复杂句式）
- **对话式交互**: 终端风格Web UI，终端的仪式感体验
- **确认机制**: 增删改操作必须二次确认，防误操作
- **多成员支持**: 爸爸/妈妈/女儿三个家庭成员
- **完整文档**: 包含设计文档、用户手册、测试报告、实现步骤

## 二、研发历程

### 2.1 阶段一：基础架构搭建

1. **数据库设计**: SQLite `money_notes` 表 + 4个索引
2. **Agent引擎**: 基于MiMo API的LLM调用封装，意图识别框架
3. **Flask API**: 12个RESTful端点，支持前后端分离

### 2.2 阶段二：核心功能开发

1. **记账功能**: 单条记账 → 支持"确认/取消"交互
2. **查询功能**: 按时间/成员/项目/类别多维查询
3. **汇总统计**: 收支汇总、成员汇总、类别汇总
4. **删除功能**: 模糊匹配 + 确认删除

### 2.3 阶段三：优化迭代

1. **多记录支持**: 一句话多条记账（"又"、"然后"等连接词）
2. **默认值优化**: 日期默认今天，成员默认"我"，item用category补
3. **删除模糊匹配**: 去除后缀和前缀后重试
4. **推理模型参数**: max_tokens从500调至2000解决空内容问题

### 2.4 阶段四：前端开发

1. **终端风格UI**: 深色主题、等宽字体、左侧面板+右侧对话区
2. **实时统计**: 收入/支出/结余卡片自动刷新
3. **记录列表**: 最近记录实时展示
4. **弹窗确认**: 清空数据等危险操作弹窗确认

### 2.5 阶段五：测试与文档

1. **测试脚本**: 6个测试用例覆盖记账/查询/删除
2. **数据库测试**: CRUD基础操作验证
3. **文档编写**: design_doc.md, user_manual.md, test_results.md, implementation_steps.md

## 三、关键技术决策

### 3.1 为什么选MiMo v2.5-pro？

| 考量 | 说明 |
|------|------|
| OpenAI兼容API | 可直接用 `openai` SDK，零适配成本 |
| 中文能力强 | 国产大模型，自然语言理解准确 |
| 推理能力强 | 能理解复杂句式（"又"、"然后"等） |
| 结构化输出 | 低温度下稳定输出JSON |

### 3.2 为什么选SQLite？

| 考量 | 说明 |
|------|------|
| 零配置 | 无需安装数据库服务 |
| 单文件 | 便携，整个项目可复制迁移 |
| 足够用 | 家庭记账数据量小，SQLite性能完全够 |

### 3.3 为什么用Flask而非FastAPI？

| 考量 | 说明 |
|------|------|
| 简单项目 | 无高并发需求 |
| 生态成熟 | 文档多，坑少 |
| 模板集成 | 直接 `send_from_directory` 提供静态文件 |

### 3.4 为什么前端用纯HTML而非框架？

- 单页应用无需React/Vue
- 终端风格不需要复杂组件
- 零构建步骤，直接打开即可

## 四、遇到的问题与解决方案

| 问题 | 现象 | 根因 | 解决方案 |
|------|------|------|----------|
| **LLM返回空内容** | `content=""`, `finish_reason=length` | 推理模型的reasoning_tokens占满max_tokens | `max_tokens` 从500→2000 |
| **SQLite线程错误** | `SQLite objects created in a thread...` | Flask debug模式多线程加载器 | `check_same_thread=False` + `debug=False` |
| **JSON解析失败** | LLM返回markdown包裹的JSON | LLM默认行为 | 正则 `r'\{[\s\S]*\}'` 提取 |
| **删除找不到记录** | 用户说"旅游团费用"，DB存"旅游团" | LLM提取和DB不完全一致 | 多层模糊匹配回退 |
| **成员缺失** | 用户说"买三体花了50元"没说谁 | 输入不完整 | 默认member="我" |
| **多记录拆不开** | "买了奔驰又买了衣服"只记一条 | LLM未识别多记录 | 系统提示词增加拆分规则 |
| **端口被占用** | `Address already in use` | 上次进程未完全退出 | `fuser -k 5000/tcp` |

## 六、技术特色

### 6.1 纯LLM驱动

整个项目没有使用任何规则引擎或正则匹配用户意图。所有自然语言理解完全依赖LLM，包括：
- 意图分类（10种）
- 信息提取（日期、成员、金额、类别、项目）
- 多记录拆分
- 别名识别（老爸=爸爸，闺女=女儿）

### 6.2 终端仪式感

前端完全模拟终端操作体验：
- 绿色 `$` prompt
- 系统消息彩色区分
- 左侧统计面板类似IDE侧边栏
- 等宽字体渲染

### 6.3 安全确认机制

所有修改操作（增、删、清空）都经过二次确认，避免误操作。确认流程统一使用 `pending_confirmations` 缓存管理。
