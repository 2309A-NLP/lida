## 一、研发历程

### 1.1 项目起源

本项目基于开源项目 **Linly-Talker**（Kedreamix/Linly-Talker）进行二次改造，增加法律知识检索增强（RAG）能力，打造面向中国法律咨询场景的 **法小助·法律数字人咨询系统**。

**原项目定位**: 通用数字人智能对话系统
**改造后定位**: 法律垂直领域的AI数字人咨询系统

### 1.2 核心技术栈

| 领域 | 技术 | 说明 |
|------|------|------|
| **LLM** | ChatGPT / Qwen / Gemini / ChatGLM | 多模型对话引擎 |
| **RAG** | TF-IDF + jieba + scikit-learn | 法律知识检索增强 |
| **ASR** | Whisper / FunASR / OmniSenseVoice | 语音识别 |
| **TTS** | EdgeTTS / PaddleTTS / CosyVoice / GPT-SoVITS | 语音合成 |
| **数字人** | SadTalker / Wav2Lip / MuseTalk / ER-NeRF | 数字人生成 |
| **Web** | Gradio / Python HTTP Server | Web界面 |
| **云部署** | AutoDL / CodeWithGPU | 云端GPU部署 |

## 二、关键技术点研发

### 2.1 LegalRAG 法律知识检索增强

**研发重点**:
1. **TF-IDF + jieba 法律文本检索**: 针对法律文书的专业分词和检索优化
2. **条款级分割**: 自动识别「第X条」格式，精准定位法律条款
3. **双模式回答**: API Key模式下LLM增强回答；无Key模式下结构化兜底
4. **完全兼容原接口**: 通过 `generate(question)` 方法无缝接入原 LLM 框架

**设计决策**:
- 不引入向量数据库（如 Chroma/FAISS），保持轻量无额外依赖
- 使用 sklearn 的 TfidfVectorizer，仅需 scikit-learn + jieba 两个包
- 法律知识库用纯文本 .txt 文件，便于非技术人员维护

### 2.2 工厂模式LLM管理

```python
class LLM:
    def init_model(self, model_name, ...):
        # 统一的模型初始化入口
        if model_name == 'LegalRAG':
            llm = LegalRAG(...)
        elif model_name == 'ChatGPT':
            llm = ChatGPT(...)
        ...
```

**研发要点**:
- 8种LLM通过工厂类统一管理
- 所有模型实现相同的 `generate()` 接口
- `LegalRAG` 作为插件式模块接入，不修改原有架构

### 2.3 法律知识库构建

**9部核心法律知识库**（`legal_kb/` 目录）：
- 覆盖民法、刑法、劳动法、公司法、消费者权益保护法等主要法律
- 每部法律按条款分割，支持精确引用
- 关键词增强文件，提升检索命中率

## 五、技术特色

### 5.1 轻量级RAG方案
- **零额外基础设施**: 无需向量数据库、无需GPU、无需云服务
- **秒级启动**: Python脚本直接运行
- **纯文本可维护**: 法律知识用 .txt 即可更新

### 5.2 渐进式能力
```
无API Key → 结构化法条检索（有法律依据，但无自然语言解释）
有API Key → LLM增强回答（自然语言 + 法条引用）
有GPU → 完整数字人体验（语音 + 形象 + 对话）
```

### 5.3 法律领域垂直优化
- 法律术语分词优化
- 条款级精确检索
- 回答强制引用法条
- 专业法律免责声明

## 六、局限与未来方向

### 6.1 当前局限
- TF-IDF 检索不如向量数据库语义理解准确
- 知识库目前仅9部法律，未覆盖全部法律领域
- LLM断电模式下回答较为机械

### 6.2 改进方向
- 升级为向量数据库（ChromaDB / FAISS）提升语义检索
- 引入法律领域微调模型（如 LawGPT）
- 增加更多法律（行政法、诉讼法等）
- 对接司法部公开案例库
- 支持 PDF 文档格式的法律知识导入
