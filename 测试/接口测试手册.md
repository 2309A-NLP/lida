# 接口测试手册

## 测试前准备

确保服务运行在 http://127.0.0.1:8080，依赖服务（Redis / MySQL / Milvus）按需启动。

## 测试用例编写约定

- 每条测试包含：测试名称、前置条件、请求参数、预期结果、验证方法
- 正常场景（Happy Path）：期望 HTTP 200 + 正确响应体
- 异常场景（Error Path）：期望对应 HTTP 4xx/5xx + 错误信息

## 1. GET /roles — 获取角色列表

### 功能说明
返回所有可用的AI角色信息（心理医生、精神科医生）。

### 正常场景

| 编号 | 名称 | 前置条件 | 请求 | 预期结果 | 验证方法 |
|---|---|---|---|---|---|
| ROL-001 | 获取全部角色 | 服务启动正常 | GET /roles | 200 OK，返回 {"roles": [...]} | roles 字段为列表，长度 >= 2 |
| ROL-002 | 验证角色字段完整性 | 同上 | GET /roles | 200 OK | 每个角色包含 id, name, title, description, welcome, tags |

### 异常场景

| 编号 | 名称 | 前置条件 | 请求 | 预期结果 |
|---|---|---|---|---|
| ROL-003 | 服务未启动 | 服务停止 | GET /roles | Connection Refused |

### 响应结构示例
```json
{
  "roles": [
    {
      "id": "char_lin",
      "name": "林语薇",
      "title": "心理医生",
      "description": "温暖共情的倾听者...",
      "welcome": "你好，我是林语薇...",
      "tags": ["心理", "焦虑", "情绪", "心理咨询"]
    },
    {
      "id": "char_chen",
      "name": "陈志远",
      "title": "精神科医生",
      "description": "从医二十年的精神科专家...",
      "welcome": "你好，我是陈志远...",
      "tags": ["精神", "疾病", "诊断", "治疗"]
    }
  ]
}
```

## 2. POST /register — 用户注册

### 功能说明
注册新用户，用户名唯一，密码使用 bcrypt 加密存储。

### 请求模型
```json
{
  "username": "string (3-50字符，字母数字)",
  "password": "string (6-100字符)",
  "email": "string (可选，需含@)"
}
```

### 正常场景

| 编号 | 名称 | 请求体 | 预期结果 |
|---|---|---|---|
| REG-001 | 正常注册 | {"username": "testuser", "password": "test123456", "email": "test@test.com"} | 200 OK，{"success": true, "message": "注册成功"} |
| REG-002 | 注册不带邮箱 | {"username": "testuser2", "password": "test123456"} | 200 OK，注册成功 |

### 异常场景

| 编号 | 名称 | 请求体 | 预期结果 | 说明 |
|---|---|---|---|---|
| REG-003 | 用户名已存在 | {"username": "testuser", "password": "test123456"} | 400 Bad Request | 重复注册同一用户名 |
| REG-004 | 用户名过短 | {"username": "ab", "password": "test123456"} | 422 Unprocessable Entity | min_length=3 校验失败 |
| REG-005 | 用户名含特殊字符 | {"username": "user@name", "password": "test123456"} | 422 Unprocessable Entity | 仅允许字母数字 |
| REG-006 | 密码过短 | {"username": "newuser", "password": "12345"} | 422 Unprocessable Entity | min_length=6 校验失败 |
| REG-007 | 缺少必填字段 | {"username": "newuser"} | 422 Unprocessable Entity | password 缺失 |
| REG-008 | 邮箱格式无效 | {"username": "newuser", "password": "test123456", "email": "notanemail"} | 422 Unprocessable Entity | 缺少 @ 符号 |

## 4. POST /chat — 发送聊天消息（核心RAG功能）

### 功能说明
向指定角色发送消息，系统从知识库检索相关内容作为上下文，调用大语言模型生成专业回复。

### 请求模型
```json
{
  "user_id": "string (1-100字符)",
  "role_id": "string (取值: char_lin 或 char_chen)",
  "message": "string (1-2000字符)"
}
```

### 响应模型
```json
{
  "response": "string (AI回复内容)",
  "chat_id": "string (UUID)"
}
```

### 正常场景

| 编号 | 名称 | 前置条件 | 请求体 | 预期结果 | 验证方法 |
|---|---|---|---|---|---|
| CHAT-001 | 心理医生聊天 | 角色知识库已加载 | {"user_id": "testuser", "role_id": "char_lin", "message": "我最近总是感到紧张不安"} | 200 OK | response 为有意义的中文内容，chat_id 为 UUID 格式 |
| CHAT-002 | 精神科医生聊天 | 同上 | {"user_id": "testuser", "role_id": "char_chen", "message": "什么是精神分裂症？"} | 200 OK | 同上 |
| CHAT-003 | 短消息聊天 | 同上 | {"user_id": "testuser", "role_id": "char_lin", "message": "你好"} | 200 OK | 返回欢迎语或问候 |
| CHAT-004 | 连续对话 | 先发一条消息，再发第二条 | 第二条消息 | 200 OK | AI能引用上下文（对话历史已保存） |

### 异常场景

| 编号 | 名称 | 请求体 | 预期结果 | 说明 |
|---|---|---|---|---|
| CHAT-005 | 无效角色ID | {"user_id": "testuser", "role_id": "invalid", "message": "hi"} | 422 Unprocessable Entity | role_id 仅允许 char_lin/char_chen |
| CHAT-006 | 空消息 | {"user_id": "testuser", "role_id": "char_lin", "message": ""} | 422 Unprocessable Entity | min_length=1 校验 |
| CHAT-007 | 消息超长 | message 字段 > 2000 字符 | 422 Unprocessable Entity | max_length=2000 校验 |
| CHAT-008 | 缺少 user_id | {"role_id": "char_lin", "message": "hi"} | 422 Unprocessable Entity | |
| CHAT-009 | 模型调用异常 | AI服务不可用 | 500 Internal Server Error | 需配置异常处理 |

## 5. GET /chat/history — 获取聊天历史

### 功能说明
获取指定用户与指定角色的历史聊天记录，支持分页（limit 参数）。

### 请求参数
- user_id: string (路径参数)
- role_id: string (路径参数)
- limit: int (查询参数，可选，默认100)

### 正常场景

| 编号 | 名称 | 前置条件 | 请求 | 预期结果 |
|---|---|---|---|---|
| HIS-001 | 获取有消息的历史 | 已发送至少2条消息 | GET /chat/history/{user_id}/char_lin | 200 OK，"history" 列表 >= 2 条 |
| HIS-002 | 获取空历史 | 新用户 | GET /chat/history/{user_id}/char_lin | 200 OK，"history" 为空列表 |
| HIS-003 | 限制返回条数 | 已发送10条 | GET /chat/history/{user_id}/char_lin?limit=3 | 200 OK，返回最多3条 |
| HIS-004 | 验证消息结构 | 同上 | GET /chat/history/{user_id}/char_lin | 每条消息包含 role, content, time 字段 |

### 异常场景

| 编号 | 名称 | 请求 | 预期结果 |
|---|---|---|---|
| HIS-005 | 不存在的用户 | GET /chat/history/nonexistent_user/char_lin | 200 OK，history 为空列表（不会报错） |
| HIS-006 | 无效 limit 参数 | GET /chat/history/{user_id}/char_lin?limit=-1 | 取决于实现，建议 422 |

## 7. DELETE /chat/history — 删除/清空聊天历史

### 功能说明
提供三个级别的历史管理操作：删除单条消息、清空所有历史、开始新对话。

### 7.1 清空历史
DELETE /chat/history/{user_id}/{role_id}

| 编号 | 名称 | 请求 | 预期结果 |
|---|---|---|---|
| DEL-001 | 清空历史 | DELETE /chat/history/{user_id}/char_lin | 200 OK，{"message": "聊天历史已清空"} |

### 7.2 删除单条消息
DELETE /chat/history/{user_id}/{role_id}/message/{index}

| 编号 | 名称 | 请求 | 预期结果 |
|---|---|---|---|
| DEL-002 | 删除有效索引 | DELETE /chat/history/{user_id}/char_lin/message/0 | 200 OK，{"message": "消息已删除", "deleted": {...}} |
| DEL-003 | 删除越界索引 | DELETE /chat/history/{user_id}/char_lin/message/999 | 400 Bad Request |
| DEL-004 | 删除负数索引 | DELETE /chat/history/{user_id}/char_lin/message/-1 | 400 Bad Request |

### 7.3 开始新对话
POST /start_new_chat/{user_id}/{role_id}

| 编号 | 名称 | 请求 | 预期结果 |
|---|---|---|---|
| DEL-005 | 开始新对话 | POST /start_new_chat/{user_id}/char_lin | 200 OK，包含 welcome 消息，历史已清空 |

## 8. POST /knowledge/add — 添加知识库文档

### 功能说明
为指定角色的知识库添加新的知识段落。

### 请求模型
```json
{
  "role_id": "string (char_lin 或 char_chen)",
  "content": "string (1-10000字符，知识内容)",
  "title": "string (可选，最多200字符)"
}
```

### 正常场景

| 编号 | 名称 | 请求体 | 预期结果 |
|---|---|---|---|
| KNW-001 | 添加文档 | {"role_id": "char_lin", "content": "认知行为疗法(CBT)...", "title": "CBT介绍"} | 200 OK，{"success": true, "message": "文档添加成功"} |
| KNW-002 | 添加文档无标题 | {"role_id": "char_chen", "content": "精神分裂症诊断标准..."} | 200 OK |
| KNW-003 | 添加后检索验证 | 同上，然后搜索 | 新增内容能被检索到 |

### 异常场景

| 编号 | 名称 | 请求体 | 预期结果 | 说明 |
|---|---|---|---|---|
| KNW-004 | 无效角色ID | {"role_id": "invalid", "content": "test"} | 422 | |
| KNW-005 | 空内容 | {"role_id": "char_lin", "content": ""} | 422 | min_length=1 校验 |
| KNW-006 | 内容超长 | content > 10000 字符 | 422 | max_length=10000 校验 |

## 9. POST /knowledge/reload — 重新加载知识库

### 功能说明
清空内存知识库并从文件系统重新加载所有角色的知识库文件。

### 正常场景

| 编号 | 名称 | 请求 | 预期结果 | 验证方法 |
|---|---|---|---|---|
| RLD-001 | 重新加载 | POST /knowledge/reload | 200 OK，{"success": true, "message": "知识库重新加载完成", "stats": {...}} | stats 字段包含各角色的条目数 |
| RLD-002 | 文件变更后重载 | 先修改 text_data 中的文件 | 同上 | 再次搜索确认新内容已加载 |

### 异常场景

| 编号 | 名称 | 前置条件 | 预期结果 |
|---|---|---|---|
| RLD-003 | 文件被删除 | 知识库文件不存在 | 200 OK，stats 中各角色条目数为 0 |
| RLD-004 | 文件编码错误 | 文件非 UTF-8编码 | 200 OK（该角色加载失败，其他正常） |
