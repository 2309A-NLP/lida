# 代码结构说明

项目采用五层架构设计：配置层 -> 接口层 -> 业务逻辑层 -> 数据层 -> 模型层，外加工具层。

```
main.py                         # 应用入口
config/settings.py              # 配置层
api/routes.py                   # 接口层
service/                        # 业务逻辑层
  chat_service.py
  knowledge_service.py
  auth_service.py
  role_service.py
data/                           # 数据层
  redis_client.py
  mysql_client.py
  milvus_client.py
model/llm_model.py              # 模型层
utils/                          # 工具层
  logger.py
  error_handler.py
  encoder.py
```

---

## 主入口: main.py

**职责**：FastAPI 应用启动、中间件注册、静态文件挂载、静态页面路由、命令行参数解析。

**关键类/函数**：
- `app = FastAPI(...)` — 创建 FastAPI 实例
- `main()` — 解析命令行参数（--host/--port/--reload）并启动 uvicorn
- `_serve_page(filename)` — 统一服务静态 HTML 页面
- `root()` / `characters_page()` / `chat_page()` / `architecture_page()` — 各页面路由

**依赖注入**：
- 导入 `api/routes.py` 的 `router` 注册 API 路由
- 导入 `config/settings.py` 的 `settings` 获取应用配置
- 导入 `utils/error_handler.py` 的异常处理器

---

## 配置层: config/settings.py

**职责**：集中管理所有配置参数，从 .env 文件或环境变量读取配置值。

**数据模型**（使用 Pydantic BaseModel）：

| 模型类 | 配置项 | 说明 |
|--------|--------|------|
| DatabaseSettings | mysql_host/port/user/password/database | MySQL 连接配置 |
| DatabaseSettings | milvus_host/port/collection | Milvus 向量数据库配置 |
| DatabaseSettings | redis_host/port/db | Redis 缓存配置 |
| ModelSettings | model_type/api_key/api_url | 大模型 API 配置 |
| ModelSettings | temperature/max_tokens | 模型生成参数 |
| EmbeddingSettings | bge_m3_model_path | BGE-M3 嵌入模型路径 |
| EmbeddingSettings | bge_reranker_model_path | BGE-Reranker 重排序模型路径 |
| EmbeddingSettings | embedding_dim/embedding_model_type | 嵌入维度与类型 |
| EmbeddingSettings | use_local_embedding | 是否使用本地嵌入模型 |
| AppSettings | app_name/version/debug | 应用基本信息 |
| AppSettings | host/port | 服务监听地址 |
| KnowledgeSettings | knowledge_dir | 知识库文件目录 |
| KnowledgeSettings | top_k/hybrid_search_weight/bm25_weight/rerank_top_n | RAG 检索参数 |

**设计要点**：
- `load_dotenv()` 自动加载 .env 文件
- 所有字段有默认值，防止配置缺失导致启动失败
- 全局单例 `settings = Settings()` 供全项目使用

## 接口层: api/routes.py

**职责**：定义所有 RESTful API 端点、请求数据模型验证、错误返回。

**数据模型**：
- `RegisterRequest` — 注册请求（username, password, email），含字段验证
- `LoginRequest` — 登录请求（username, password）
- `ChatRequest` — 聊天请求（user_id, role_id, message），role_id 限定 char_lin/char_chen
- `ChatResponse` — 聊天响应（response, chat_id）
- `KnowledgeRequest` — 知识库添加请求（role_id, content, title）

**API 端点**：

| 方法 | 路径 | 功能 | 标签 |
|------|------|------|------|
| GET | /roles | 获取所有角色列表 | 角色管理 |
| POST | /register | 用户注册 | 用户认证 |
| POST | /login | 用户登录 | 用户认证 |
| POST | /chat | 发送聊天消息 | 聊天功能 |
| GET | /chat/history/{user_id}/{role_id} | 获取聊天历史 | 聊天历史 |
| DELETE | /chat/history/{user_id}/{role_id} | 清空聊天历史 | 聊天历史 |
| DELETE | /chat/history/{user_id}/{role_id}/message/{index} | 删除单条消息 | 聊天历史 |
| GET | /chat/history/list | 获取会话列表 | 聊天历史 |
| POST | /start_new_chat/{user_id}/{role_id} | 开始新对话 | 聊天历史 |
| POST | /knowledge/add | 添加知识文档 | 知识库管理 |
| DELETE | /knowledge/clear/{role_id} | 清空知识库 | 知识库管理 |
| POST | /knowledge/reload | 重新加载知识库 | 知识库管理 |
| GET | /knowledge/search | 搜索知识库 | 知识库管理 |

**设计要点**：
- 模块级 Service 单例，避免每次请求重新创建
- 使用 Pydantic field_validator 做输入校验

## 业务逻辑层 - service/chat_service.py

**职责**：聊天系统的核心服务，处理用户消息并生成 AI 回复。

**关键方法**：
- `process_message(user_id, role_id, message)` — 核心方法
  1. 从 Redis 获取最近 50 条聊天历史
  2. 从 KnowledgeService 检索相关知识
  3. 调用 LLMModel.generate() 生成 AI 回复
  4. 将用户消息和 AI 回复存入 Redis
  5. 返回回复内容和 chat_id
- `get_history(user_id, role_id, limit)` — 获取聊天历史
- `clear_history(user_id, role_id)` — 清空历史
- `delete_message(user_id, role_id, index)` — 按索引删除消息
- `get_history_list(user_id)` — 获取用户所有角色的会话列表
- `start_new_chat(user_id, role_id)` — 清空历史并返回欢迎语

**设计要点**：
- KnowledgeService 使用全局单例，避免每次请求重新加载模型
- Redis 返回的消息顺序为新->旧，翻转为旧->新供 LLM 使用

---

## 业务逻辑层 - service/knowledge_service.py

**职责**：RAG 系统的核心服务，管理知识库的加载、检索和更新。

**关键方法**：
- `_load_knowledge()` — 从 text_data/ 目录加载各角色的知识库文件
- `search(query, role_id, top_k)` — 混合检索（优先 Milvus 向量检索，降级到关键词匹配）
- `add_document(role_id, content, title)` — 动态添加知识文档
- `clear_knowledge(role_id)` — 清空指定角色的知识库
- `reload_knowledge()` — 重新加载全部知识库
- `get_knowledge_count(role_id)` — 获取知识库条目数

**RAG 检索流程**：
1. 用户问题 -> 向量化（BGE-M3）-> Milvus 相似度搜索
2. 同时进行 BM25 关键词检索
3. 混合评分（权重可配：hybrid_weight + bm25_weight）
4. BGE-Reranker 重排序
5. 返回 top_k 条相关知识

**降级策略**：
- Milvus 不可用时使用内存向量搜索（余弦相似度）
- BM25 不可用时使用 jieba 分词关键词匹配

**知识库文件映射**：
```
char_lin  -> text_data/心理医生.txt
char_chen -> text_data/精神科医生.txt
char_lawyer -> text_data/律师.txt（可选）
```

## 业务逻辑层 - service/auth_service.py

**职责**：用户认证服务，管理注册/登录/用户信息查询。

**关键方法**：
- `register(username, password, email)` — 注册新用户（密码 bcrypt 加密）
- `login(username, password)` — 登录验证
- `get_user(user_id)` — 获取用户信息

**安全特性**：
- 密码使用 bcrypt 加密存储（自动生成随机 salt）
- 验证时间与密码长度无关（防时序攻击）
- 不存储明文密码

**存储策略**：
- 优先 MySQL（自动创建 users 表）
- MySQL 不可用时自动降级到内存存储（Dict）

**用户表结构**：
```sql
CREATE TABLE users (
    id VARCHAR(36) PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    email VARCHAR(100),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 模型层: model/llm_model.py

**职责**：调用 DeepSeek API 生成 AI 回复。

**关键方法**：
- `generate(message, role_id, history, knowledge)` — 核心生成方法
- `_build_system_prompt(role_id, knowledge)` — 构建系统提示词（角色设定 + 知识上下文）
- `_build_messages(system_prompt, history, message)` — 构建 API 消息列表
- `_call_api(messages)` — 调用 DeepSeek Chat API
- `_get_fallback(message, role_id)` — API 失败时的备用回复

**API 调用**：POST 请求到 `MODEL_ENDPOINT`，使用 `MODEL_API_KEY` 认证

**备用回复**：当 API 调用失败时，使用预定义的角色相关回复（随机选择），确保系统可用性

## 数据层: data/redis_client.py

**职责**：Redis 缓存客户端，存储聊天历史和会话数据。

**关键方法**：
- `get_chat_history(user_id, role_id, limit)` — 获取聊天历史
- `add_chat_message(user_id, role_id, message)` — 添加聊天消息
- `clear_chat_history(user_id, role_id)` — 清空历史
- `delete_message_at(user_id, role_id, index)` — 按索引删除消息

**存储结构**：
```
chat:{user_id}:{role_id} -> List[JSON 消息]
每条消息: {"role": "user|assistant", "content": "文本", "time": "ISO时间"}
```

**降级策略**：Redis 连接失败时自动切换到 `memory_store`（Dict），仅保留最近 20 条消息。

## 数据层: data/mysql_client.py

**职责**：MySQL 数据库客户端，持久化存储用户数据。

**关键方法**：
- `init_tables()` — 初始化 users 和 chat_history 表
- `save_message(user_id, role_id, message_role, content)` — 保存聊天消息
- `get_history(user_id, role_id, limit)` — 获取聊天历史

**表结构**：
- users — 用户信息（id, username, password, email, created_at）
- chat_history — 聊天记录（id, user_id, role_id, message_role, content, created_at）

**设计要点**：
- 每次操作后断开连接（短连接模式）
- 数据库不存在时自动创建
- 自动重试机制

## 数据层: data/milvus_client.py

**职责**：Milvus 向量数据库客户端，支持向量检索 + BM25 + Rerank 混合检索。

**关键方法**：
- `generate_embedding(text)` — BGE-M3 文本向量化
- `add_documents(documents, role_id)` — 添加文档到向量库
- `vector_search(query, role_id, top_k)` — 向量相似度搜索
- `bm25_search(query, role_id, top_k)` — BM25 关键词检索
- `hybrid_search(query, role_id, top_k)` — 混合检索（向量+BM25+Rerank）
- `rerank(query, candidates, top_k)` — BGE-Reranker 重排序
- `search(query, role_id, top_k)` — 统一搜索入口

**集合结构**：
```
id (INT64, 主键), role_id (VARCHAR), content (VARCHAR 5000), embedding (FLOAT_VECTOR 1024维)
```

**设计要点**：
- 支持 Milvus 在线模式和内存模式双模运行
- BGE-M3 返回的嵌入格式多样，`_extract_dense_vector()` 统一提取
- 混合检索权重可配置

## 工具层: utils/error_handler.py

**职责**：统一异常处理，返回标准化 JSON 错误响应。

**关键类/函数**：
- `AppException` — 自定义业务异常类（code, message, status_code, detail）
- `http_exception_handler` — HTTP 异常处理器
- `global_exception_handler` — 全局异常处理器（区分 HTTPException/AppException/其他）

**响应格式**：
```json
{"success": false, "error": {"code": "ERROR_CODE", "message": "错误描述"}}
```
