# 快速开发备忘录

## 常用命令

### 启动服务

```bash
# 标准启动（开发模式，热重载）
uvicorn main:app --host 0.0.0.0 --port 8080 --reload

# 或使用主入口脚本
python main.py --host 0.0.0.0 --port 8080 --reload

# 生产模式启动
uvicorn main:app --host 0.0.0.0 --port 8080 --workers 4

# 自定义端口
python main.py --port 8000
```

### 虚拟环境

```bash
# Windows 激活
venv\Scripts\activate

# Linux/Mac 激活
source venv/bin/activate

# 退出
deactivate
```

### 依赖管理

```bash
# 安装所有依赖
pip install -r requirements.txt

# 安装新包后更新 requirements.txt
pip freeze > requirements.txt

# 查看已安装包列表
pip list
```

### Docker 部署

```bash
# 启动所有服务
docker compose up -d

# 查看状态
docker compose ps

# 查看日志
docker compose logs -f

# 停止所有服务
docker compose down

# 扩展到 5 个后端实例
docker compose scale backend=5

# 重建镜像后启动
docker compose up -d --build
```

### Redis 操作

```bash
# 连接 Redis
redis-cli

# 查看所有聊天历史键
KEYS chat:*

# 查看特定用户的聊天记录
LRANGE chat:user_1:char_lin 0 -1

# 清除所有聊天数据
FLUSHDB

# 监控实时命令
MONITOR
```

### MySQL 操作

```bash
# 连接数据库
mysql -u root -p rag_chatbot

# 查看用户表
SELECT * FROM users;

# 查看聊天历史表
SELECT * FROM chat_history WHERE user_id='user_1' LIMIT 10;

# 清空聊天历史
DELETE FROM chat_history;
```

### API 测试

```bash
# 获取角色列表
curl http://localhost:8080/roles

# 用户注册
curl -X POST http://localhost:8080/register \
  -H "Content-Type: application/json" \
  -d '{"username":"test1","password":"123456"}'

# 用户登录
curl -X POST http://localhost:8080/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test1","password":"123456"}'

# 发送聊天消息
curl -X POST http://localhost:8080/chat \
  -H "Content-Type: application/json" \
  -d '{"user_id":"user_1","role_id":"char_lin","message":"我最近总是失眠"}'

# 查看聊天历史
curl "http://localhost:8080/chat/history/user_1/char_lin?limit=10"

# 开始新对话
curl -X POST http://localhost:8080/start_new_chat/user_1/char_lin

# 添加知识库文档
curl -X POST http://localhost:8080/knowledge/add \
  -H "Content-Type: application/json" \
  -d '{"role_id":"char_lin","content":"新知识段落...","title":"新知识标题"}'

# 重新加载知识库
curl -X POST http://localhost:8080/knowledge/reload

# 搜索知识库
curl "http://localhost:8080/knowledge/search?query=焦虑&role_id=char_lin&top_k=5"
```

## 常见问题

### Q1: 启动时报 `ModuleNotFoundError: No module named 'xxx'`

**原因**：未安装依赖或虚拟环境未激活。

**解决**：
```bash
# 确认虚拟环境已激活
which python   # 应指向 venv 目录
pip list | grep xxx  # 确认包已安装
pip install xxx      # 安装缺失包
```

### Q2: 启动时报 `pymysql.err.OperationalError`

**原因**：MySQL 未启动或连接信息错误。

**解决**：确保 MySQL 服务已启动。如果不需要 MySQL，这是正常行为，系统会自动降级到内存存储。

### Q3: 聊天时 AI 回复为空或报 500 错误

**原因**：通常是 DeepSeek API 密钥无效或网络问题。

**排查**：
```bash
# 1. 确认 .env 中 MODEL_API_KEY 已填写且有效
# 2. 直接用 curl 测试 API
curl -X POST https://api.deepseek.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $MODEL_API_KEY" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"hi"}]}'
# 3. 检查是否有代理影响网络
```

### Q4: 知识库检索返回空结果

**原因**：知识库文件不存在、为空或格式问题。

**排查**：
```bash
# 1. 确认 text_data/ 目录下有对应文件
ls -la text_data/
# 2. 确认文件不为空
wc -l text_data/心理医生.txt
# 3. 确认文件格式正确（段落间有空行分割）
# 4. 调用 API 重新加载
curl -X POST http://localhost:8080/knowledge/reload
```

### Q5: 向量检索不工作 / Milvus 连接失败

**原因**：Milvus 服务未启动或模型路径错误。

**解决**：
- 设置 `USE_LOCAL_EMBEDDING=false` 使用关键词匹配降级方案
- 或启动 Milvus 服务（Docker Compose 或手动）
- 或确认 BGE-M3 模型路径正确

### Q6: Windows 下路径问题

**注意**：配置中的路径如果使用反斜杠，需要转义或使用正斜杠：
```ini
# 正确
BGE_M3_PATH=D:/BGE-M3
# 错误
BGE_M3_PATH=D:\BGE-M3
```

### Q7: Docker 部署后访问 502

**原因**：后端服务启动慢，Nginx 健康检查超时。

**解决**：等待 40 秒后刷新，或调整 `docker-compose.yml` 中的 `start_period`。

### Q8: 聊天历史不持久化

**原因**：使用内存存储模式（Redis 未连接），服务重启后数据丢失。

**解决**：启动 Redis 服务，或连接 MySQL 持久化聊天记录。

## 代码热重载

开发模式下使用 `--reload` 参数，修改代码后自动重启服务：

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8080
```

修改以下文件会自动触发重载：
- main.py
- api/routes.py
- service/*.py
- config/settings.py
- utils/*.py

注意：修改 `data/*.py` 和 `model/llm_model.py` 也会触发重载，但 Service 层的单例对象（如 KnowledgeService 的模型实例）需要手动重新加载。
