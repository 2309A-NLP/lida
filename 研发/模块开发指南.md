# 模块开发指南

## 一、如何添加新角色

### 1. 在 RoleService 中注册新角色

编辑 `service/role_service.py`，在 `self.roles` 列表中添加新角色：

```python
self.roles = [
    # ... 已有角色 ...
    {
        "id": "char_lawyer",         # 角色唯一标识，格式建议 char_xxx
        "name": "张明远",             # 角色名称
        "title": "律师",              # 角色头衔/职业
        "description": "从业十五年的资深律师，擅长民商事诉讼、合同纠纷和知识产权案件。",
        "welcome": "你好，我是张明远律师。有什么法律问题需要咨询吗？",
        "tags": ["法律", "合同", "纠纷", "诉讼"]
    },
]
```

### 2. 添加系统提示词

在 `service/role_service.py` 的 `get_role_prompt()` 方法中添加：

```python
prompts = {
    # ... 已有提示词 ...
    "char_lawyer": "你是张明远，一位从业十五年的资深律师。你擅长民商事诉讼、合同纠纷和知识产权案件。请保持专业严谨的态度，为用户提供法律建议。请注意，你的回答不构成正式法律意见，建议用户咨询执业律师。"
}
```

### 3. 添加欢迎语

在 `service/chat_service.py` 的 `__init__()` 中：

```python
self.role_welcome = {
    # ... 已有欢迎语 ...
    "char_lawyer": "你好，我是张明远律师。有什么法律问题需要咨询吗？"
}
```

### 4. 创建知识库文件

在 `text_data/` 目录下创建对应角色的知识库文件，例如 `律师.txt`。

格式要求：
- UTF-8 编码
- 每个知识点段落之间用空行分隔
- 内容应与角色专业领域相关

### 5. 更新知识库加载映射

在 `service/knowledge_service.py` 的 `_load_knowledge()` 方法中更新 `filenames` 字典：

```python
filenames = {
    "char_lin": "心理医生.txt",
    "char_chen": "精神科医生.txt",
    "char_lawyer": "律师.txt",     # 新增
}
```

### 6. 更新 API 路由验证（可选）

如果在 `api/routes.py` 中 `ChatRequest` 和 `KnowledgeRequest` 的验证器限制了 role_id，需要同步更新：

```python
@field_validator('role_id')
@classmethod
def validate_role_id(cls, v):
    if v not in ("char_lin", "char_chen", "char_lawyer"):  # 添加新角色 ID
        raise ValueError("无效的角色ID")
    return v
```

### 7. 更新前端角色显示

在 `template/characters.html` 中添加新角色的卡片展示。

### 8. 添加备用回复（可选）

在 `model/llm_model.py` 的 `_get_fallback()` 中添加：

```python
fallbacks = {
    # ... 已有 fallback ...
    "char_lawyer": [
        "根据您描述的情况，我需要了解更多的案件细节。",
        "从法律角度来看，这个问题涉及多个法律条文。",
        "建议您收集相关证据材料，包括合同、邮件等。"
    ]
}
```

## 二、如何扩展知识库

### 方法 1：通过 API 动态添加

使用 POST 请求添加知识文档：

```bash
curl -X POST http://localhost:8080/knowledge/add \
  -H "Content-Type: application/json" \
  -d '{
    "role_id": "char_lin",
    "content": "认知行为疗法(CBT)是一种有效的心理治疗方法...",
    "title": "CBT疗法简介"
  }'
```

### 方法 2：直接编辑知识库文件

编辑 `text_data/` 目录下的对应文件：

```bash
# 编辑心理医生知识库
vim text_data/心理医生.txt

# 编辑后通过 API 重新加载
curl -X POST http://localhost:8080/knowledge/reload
```

### 方法 3：上传 PDF 并转换

系统目前不支持直接解析 PDF，但可以：

1. 将 PDF 放入 `data/` 对应目录（如 `data/心里医生PDF/`）
2. 手动提取文本内容添加到 `text_data/` 对应的 txt 文件
3. 调用重新加载 API

### 方法 4：支持新文件格式（扩展开发）

如需支持 PDF/Word 自动解析，修改 `service/knowledge_service.py` 的 `_load_knowledge()` 方法，增加文件格式检测和解析逻辑。推荐使用：
- PyMuPDF (fitz) — PDF 解析
- python-docx — Word 文档解析

### 知识库文件格式规范

每个知识库文件建议：
- 按主题分段，段落间空行
- 每段 200-1000 字为宜
- 专业术语要准确
- 避免过时/矛盾的信息

## 三、如何配置新模型

### 切换大语言模型

编辑 `.env` 文件中的模型相关配置：

```ini
# 将 MODEL_TYPE 改为 new_provider
MODEL_TYPE=new_provider

# 修改 API 地址
MODEL_ENDPOINT=https://api.new-provider.com/v1/chat/completions

# 修改 API 密钥
MODEL_API_KEY=sk-new-api-key

# 调整生成参数
TEMPERATURE=0.8
MAX_TOKENS=4096
```

如果新模型的 API 格式与 OpenAI 兼容（即 messages 格式），则无需修改代码。否则需要修改 `model/llm_model.py` 中的 `_call_api()` 方法。

### 示例：适配非 OpenAI 兼容 API

修改 `model/llm_model.py` 的 `_call_api()`：

```python
def _call_api(self, messages: List[Dict]) -> Optional[str]:
    if settings.model.model_type == "custom_api":
        return self._call_custom_api(messages)
    # 原有的 OpenAI 兼容 API 调用
    ...

def _call_custom_api(self, messages: List[Dict]) -> Optional[str]:
    # 自定义 API 调用逻辑
    headers = {
        "Content-Type": "application/json",
        "X-API-Key": self.api_key
    }
    payload = {
        "prompt": self._convert_messages_to_prompt(messages),
        "max_tokens": settings.model.max_tokens,
        "temperature": self.temperature
    }
    try:
        response = requests.post(self.api_url, headers=headers, json=payload, timeout=30)
        if response.status_code == 200:
            return response.json()["text"]  # 根据实际 API 响应格式调整
        return None
    except Exception as e:
        print(f"[LLM] 自定义API调用失败: {e}")
        return None
```

### 切换嵌入模型

BGE-M3 是默认嵌入模型。如需切换：

1. 修改 `.env`：
```ini
EMBEDDING_MODEL_TYPE=new_model_name
BGE_M3_PATH=/path/to/new/embedding/model
EMBEDDING_DIM=768   # 根据新模型调整向量维度
USE_LOCAL_EMBEDDING=true
```

2. 如需使用 API 形式的嵌入服务（而非本地模型），修改 `data/milvus_client.py` 的 `generate_embedding()` 方法：

```python
def generate_embedding(self, text: str) -> List[float]:
    if settings.embedding.embedding_model_type == "api":
        # 调用嵌入 API
        response = requests.post(
            "https://api.embedding-service.com/v1/embeddings",
            headers={"Authorization": f"Bearer {api_key}"},
            json={"input": text, "model": "text-embedding-v3"}
        )
        return response.json()["data"][0]["embedding"]
    # 原有的本地 BGE-M3 调用
    ...
```

### 切换重排序模型

修改 `.env`：
```ini
BGE_RERANKER_PATH=/path/to/new/reranker
RERANK_TOP_N=3
```

目前使用 `AutoModelForSequenceClassification` 加载，兼容绝大多数 BGE/Cross-Encoder 类重排序模型。

## 四、整体开发流程

1. 定义需求：确定新增角色/功能
2. 角色注册：在 RoleService 中添加角色信息
3. 知识准备：创建或更新知识库文件
4. 提示词设计：编写角色系统提示词
5. 验证测试：使用 API 测试新角色对话
6. 前端适配：更新前端页面展示新角色
7. 知识库加载：调用 /knowledge/reload 使变更生效
