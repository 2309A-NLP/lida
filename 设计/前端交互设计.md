# 前端交互设计文档

## 1. 前端概述

前端采用纯 HTML / CSS / JavaScript 实现，无任何前端框架依赖。所有页面位于 `template/` 目录下，由 FastAPI 静态文件服务提供。

**页面列表:**

| 页面文件 | 路由 | 功能 |
|---------|------|------|
| index.html | GET / | 首页 / 登录注册 |
| characters.html | GET /characters.html | 角色选择 |
| chat.html | GET /chat.html | 聊天对话 |
| architecture.html | GET /architecture.html | 系统架构展示 |

## 2. 页面路由与跳转流程

### 2.1 用户旅程

```
首页 (index.html)
  |  用户登录/注册
  v
角色选择 (characters.html)
  |  选择角色
  v
聊天对话 (chat.html)
  |  发送消息/查看历史
  v
(可返回角色选择页切换角色)
```

### 2.2 页面路由映射

| 前端操作 | 路由 | 说明 |
|---------|------|------|
| 首次访问 | GET / | 加载 index.html |
| 登录成功后跳转 | window.location.href = "/characters.html" | 角色选择页 |
| 选择角色后跳转 | window.location.href = "/chat.html?role=char_lin" | 带角色参数进入聊天 |
| 点击返回按钮 | window.location.href = "/characters.html" | 返回角色选择 |
| 点击架构链接 | window.location.href = "/architecture.html" | 架构展示页 |

## 3. 首页交互设计 (index.html)

### 3.1 页面布局

```
+------------------------------------------+
|  Logo + 网站名称                          |
+------------------------------------------+
|  特色功能展示区  |  登录/注册表单         |
|  (三个卡片)      |                        |
|                  |  [用户名输入]          |
|                  |  [密码输入]            |
|                  |  [记住我] [忘记密码]   |
|                  |  [登录按钮]            |
|                  |  [注册切换]            |
+------------------------------------------+
```

### 3.2 登录流程

```
1. 用户输入用户名和密码
2. 点击"登录"按钮
3. 前端发起 POST /login 请求
4. 若成功:
   - 存储 user_id 和 username 到 localStorage
   - 跳转到 /characters.html
5. 若失败:
   - 显示错误提示 (用户名不存在 / 密码错误)
```

**localStorage 存储内容:**
```javascript
localStorage.setItem("user_id", "返回的用户ID");
localStorage.setItem("username", "用户名");
```

### 3.3 注册流程

```
1. 用户切换到注册模式 (显示注册表单)
2. 输入用户名、密码、邮箱
3. 点击"注册"按钮
4. 前端发起 POST /register 请求
5. 若成功:
   - 显示"注册成功"提示
   - 自动切换到登录模式
6. 若失败:
   - 显示错误提示 (用户名已存在 / 格式错误)
```

### 3.4 API 调用时机

| 事件 | API 调用 | 参数 |
|------|---------|------|
| 点击登录 | POST /login | {username, password} |
| 点击注册 | POST /register | {username, password, email} |

## 4. 角色选择页交互设计 (characters.html)

### 4.1 页面布局

```
+------------------------------------------+
|  返回首页链接   标题: "选择您的咨询师"    |
+------------------------------------------+
|                                            |
|  +-----------+  +-----------+              |
|  |  林语薇    |  |  陈志远   |              |
|  |  心理医生  |  |  精神科医 |              |
|  |  描述...   |  |  描述...   |              |
|  |  标签1 2   |  |  标签1 2  |              |
|  |  [开始对话] |  |  [开始对话] |              |
|  +-----------+  +-----------+              |
|                                            |
+------------------------------------------+
```

### 4.2 交互流程

```
1. 页面加载时:
   - 检查 localStorage 是否有 user_id
   - 如果没有，跳转到首页 (需要登录)
   - 发起 GET /roles 获取角色列表
   - 渲染角色卡片

2. 用户点击"开始对话":
   - 获取角色的 role_id
   - 跳转到 /chat.html?role={role_id}
```

### 4.3 API 调用时机

| 事件 | API 调用 | 说明 |
|------|---------|------|
| 页面加载 | GET /roles | 获取所有角色信息 |

## 5. 聊天页面交互设计 (chat.html)

### 5.1 页面布局

```
+--------------------------------------------------------+
|  返回按钮 | 角色头像 | 角色名 | 在线状态 | [历史] [清空] |
+--------------------------------------------------------+
|                                                        |
|  历史侧栏 (可收起)      |  消息列表区域                |
|  +-------------------+  |  +----------------------+   |
|  | 林语薇 - 最后消息 |  |  | 用户: 我最近很焦虑... |   |
|  | 陈志远 - 最后消息 |  |  | AI:  我能感受到...    |   |
|  +-------------------+  |  | 用户: 我睡不着...     |   |
|                         |  |  AI: 从临床角度来看...  |   |
|                         |  +----------------------+   |
|                         |                              |
|                         |  [输入框...] [发送]          |
+--------------------------------------------------------+
```

### 5.2 页面初始化流程

```
1. 从 URL 获取 role 参数
   - 如 /chat.html?role=char_lin
   
2. 检查 localStorage 获取 user_id
   - 如果没有，跳转到首页
   
3. 设置页面信息
   - 根据 role_id 设置角色名、头像样式、颜色主题
   
4. 加载聊天历史
   - 发起 GET /chat/history/{user_id}/{role_id}
   - 渲染历史消息列表
```

### 5.3 发送消息流程

```
1. 用户在输入框输入消息，点击发送按钮 (或按 Enter)
2. 前端校验: 消息不能为空
3. 用户消息立即显示在聊天区域 (乐观更新)
4. 显示"正在输入..."的加载动画
5. 发起 POST /chat 请求:
   {
     "user_id": "user_1",
     "role_id": "char_lin",
     "message": "用户输入的内容"
   }
6. 收到回复后:
   - 隐藏加载动画
   - 显示 AI 的回复消息
   - 自动滚动到底部
7. 若请求失败:
   - 隐藏加载动画
   - 显示错误提示
   - 用户消息保留
```

### 5.4 聊天历史侧栏

```
1. 点击侧栏按钮打开历史面板
2. 发起 GET /chat/history/list?user_id={user_id}
3. 渲染会话列表 (按最后消息时间排序)
4. 点击某个会话:
   - 切换当前角色
   - 重新加载该角色的聊天历史
   - 关闭侧栏
5. 点击删除按钮:
   - 发起 DELETE /chat/history/{user_id}/{role_id}
   - 从列表中移除该会话
```

### 5.5 开始新对话

```
1. 用户点击"新对话"按钮
2. 发起 POST /start_new_chat/{user_id}/{role_id}
3. 清空聊天区域
4. 显示欢迎语
```

### 5.6 清空历史

```
1. 用户点击"清空"按钮
2. 弹出确认对话框
3. 确认后:
   - 发起 DELETE /chat/history/{user_id}/{role_id}
   - 清空聊天区域
   - 显示角色的欢迎语
```

### 5.7 删除单条消息

```
1. 鼠标悬停在某条消息上
2. 显示删除按钮
3. 点击删除按钮
4. 发起 DELETE /chat/history/{user_id}/{role_id}/message/{index}
5. 从界面移除该消息
```

### 5.8 API 调用时机汇总

| 用户操作 | API 调用 | 说明 |
|---------|---------|------|
| 进入聊天页 | GET /chat/history/{user_id}/{role_id} | 加载历史 |
| 发送消息 | POST /chat | 发送并获取回复 |
| 打开历史侧栏 | GET /chat/history/list | 获取所有会话 |
| 切换会话 | GET /chat/history/{user_id}/{role_id} | 加载新会话历史 |
| 开始新对话 | POST /start_new_chat/{user_id}/{role_id} | 重置对话 |
| 清空历史 | DELETE /chat/history/{user_id}/{role_id} | 删除全部 |
| 删除消息 | DELETE /chat/history/{...}/message/{index} | 删除单条 |

## 6. 视觉设计风格

### 6.1 色彩系统

- 背景: 深色渐变 `#0F172A` -> `#1E293B`
- 主色: 紫色 `#6366F1` (林语薇角色主题色)
- 辅色: 绿色 `#10B981` (陈志远角色主题色)
- 强调色: 粉色 `#EC4899`
- 文字: 白色 `#F8FAFC` / 灰色 `#94A3B8`
- 卡片: 半透明 `rgba(255, 255, 255, 0.06)`

### 6.2 角色主题色

| 角色 | 主色 | 用途 |
|------|------|------|
| 林语薇 | #6366F1 (紫色) | 头像、聊天气泡、按钮 |
| 陈志远 | #10B981 (绿色) | 头像、聊天气泡、按钮 |

### 6.3 动态效果

- 页面加载动画: `slideUp` 渐入效果
- 背景呼吸动画: 径向渐变缓慢变化
- 装饰元素浮动动画
- 按钮悬停: 微上浮 + 阴影加深
- 消息出现: 淡入动画
- 打字指示器: 脉冲圆点动画

## 7. 响应式设计

- 使用 `viewport-fit=cover` 适配全面屏
- 使用 `max-width` 和百分比布局
- 移动端适配: 在较小屏幕上隐藏部分装饰元素
- 侧栏适配: 移动端全屏覆盖，桌面端半屏

## 8. 错误处理

| 场景 | 处理方式 |
|------|---------|
| API 请求失败 | 显示错误提示 Toast 通知 |
| 网络断开 | 显示"网络连接失败"提示 |
| 无效角色 ID | 跳转到角色选择页 |
| 未登录访问 | 跳转到首页登录 |
| 消息发送失败 | 保留用户消息，显示重试按钮 |
