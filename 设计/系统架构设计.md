# 系统架构设计文档

## 1. 整体架构概览

系统采用经典的分层架构（Layered Architecture），共分为 5 层，自上而下依次为：配置层、接口层、业务逻辑层、数据层和模型层。此外还包含工具层提供通用支持。

```
+------------------------------------------------------+
|                   前端 (HTML/CSS/JS)                  |
+------------------------------------------------------+
        |  HTTP 请求 (JSON)
        v
+------------------------------------------------------+
|   API 接口层 (api/routes.py)                          |
|   路由分发 / 请求校验 / 响应返回                      |
+------------------------------------------------------+
        |
        v
+------------------------------------------------------+
|   业务逻辑层 (service/)                               |
|   chat_service.py  |  knowledge_service.py            |
|   auth_service.py  |  role_service.py                 |
+------------------------------------------------------+
        |              |              |
        v              v              v
+----------------+ +-------------+ +------------------+
| 数据层 (data/)  | | 模型层      | | 配置层 (config/) |
| redis_client.py | | model/      | | settings.py      |
| mysql_client.py | | llm_model.py| |                  |
| milvus_client.py| +-------------+ |                  |
+----------------+                  +------------------+
```

## 2. 分层职责说明

### 2.1 配置层 (config/)

**文件**: config/settings.py

管理所有应用配置参数，支持从环境变量和 `.env` 文件读取。包含以下配置模块：

- `AppSettings`: 应用基本信息 (名称、版本、端口等)
- `DatabaseSettings`: 数据库连接配置 (MySQL / Redis / Milvus)
- `ModelSettings`: AI 模型配置 (API Key / 端点 / 温度参数)
- `EmbeddingSettings`: 向量嵌入模型配置 (BGE-M3 / BGE-reranker 路径)
- `KnowledgeSettings`: 知识库检索参数 (top_k / 混合检索权重)

采用 Pydantic BaseModel 实现配置的自动类型校验和默认值管理。

### 2.2 接口层 (api/)

**文件**: api/routes.py

定义所有 RESTful API 端点，作为前端与后端之间的通信桥梁。主要职责：

- 接收 HTTP 请求并解析参数
- 使用 Pydantic 模型进行请求数据校验
- 调用业务逻辑层相应服务处理方法
- 组装并返回响应数据
- 处理异常并返回友好的错误信息

### 2.3 业务逻辑层 (service/)

包含四个核心服务模块：

**ChatService** (chat_service.py): 聊天核心业务
- 接收用户消息，串联 RAG 检索和 LLM 调用
- 管理聊天历史记录
- 提供新对话、消息删除等功能

**RoleService** (role_service.py): 角色管理
- 定义和管理 AI 角色信息 (角色名称、描述、欢迎语、标签)
- 提供角色系统提示词（System Prompt）
- 支持按关键词搜索角色

**AuthService** (auth_service.py): 用户认证
- 用户注册和登录
- 密码 bcrypt 加密存储
- MySQL 优先存储，降级到内存存储

**KnowledgeService** (knowledge_service.py): 知识库服务
- 加载知识库文件到内存
- RAG 检索增强生成 (jieba 分词 + BM25 关键词匹配)
- 动态添加、清空、重新加载知识库

### 2.4 数据层 (data/)

**RedisClient** (redis_client.py): 聊天历史缓存
- 使用 Redis List 存储聊天消息
- Key 格式: `chat:{user_id}:{role_id}`
- 每条消息保留最近 20 条
- Redis 不可用时降级到字典内存存储

**MySQLClient** (mysql_client.py): 持久化存储
- 用户表 (users): 存储用户注册信息
- 聊天历史表 (chat_history): 持久化存储聊天记录
- 自动创建数据库和表

**MilvusClient** (milvus_client.py): 向量数据库 (可选)
- 使用 BGE-M3 模型进行文本向量化
- 支持 BM25 关键词检索
- 支持 BGE-reranker 重排序
- Milvus 不可用时降级到内存 BM25 检索

### 2.5 模型层 (model/)

**LLMModel** (llm_model.py): AI 模型调用
- 调用 DeepSeek API 生成回复
- 构建 System Prompt (含角色设定 + 知识库上下文)
- 构建多轮对话消息列表
- API 调用失败时返回预设的备用回复

## 3. 核心调用链

### 3.1 聊天请求完整调用链

```
用户发送消息
    |
    v
前端 POST /api/chat
    |
    v
api/routes.py -> chat() 端点
    |  请求参数校验 (user_id, role_id, message)
    v
service/chat_service.py -> process_message()
    |
    ├──> 1. data/redis_client.py -> get_chat_history()
    |      读取用户与该角色的聊天历史 (最多 50 条)
    |
    ├──> 2. service/knowledge_service.py -> search()
    |      - jieba 分词解析用户问题
    |      - 合并预定义关键词集合
    |      - BM25 关键词匹配排序
    |      - 返回 top_k 相关段落
    |
    ├──> 3. model/llm_model.py -> generate()
    |      - 构建 System Prompt (角色设定 + 知识库上下文)
    |      - 构建消息列表 (system + history + user)
    |      - 调用 DeepSeek API
    |      - 返回 AI 回复
    |
    └──> 4. data/redis_client.py -> add_chat_message()
           - 存储用户消息到 Redis
           - 存储 AI 回复到 Redis
```

### 3.2 用户注册链路

```
api/routes.py -> register() 端点
    |
    v
service/auth_service.py -> register()
    |
    ├──> (MySQL 模式) data/mysql_client.py
    |      - 检查用户名是否已存在
    |      - 插入新用户记录 (UUID + bcrypt 密码)
    |
    └──> (内存模式) 内存字典存储
```

### 3.3 知识库检索链路

```
service/knowledge_service.py -> search()
    |
    ├──> (Milvus 模式) data/milvus_client.py -> search()
    |      - BGE-M3 向量化查询
    |      - 向量相似度搜索
    |      - BM25 关键词搜索
    |      - BGE-reranker 重排序
    |
    └──> (降级模式) 内存关键词匹配
           - jieba 分词
           - 合并预定义关键词
           - 计算段落命中数
```

## 4. 优雅降级设计

系统设计了多层优雅降级机制，确保在部分组件不可用时仍能正常运行：

| 组件故障 | 降级策略 |
|---------|---------|
| Redis 不可用 | 降级到 Python 字典内存存储 |
| MySQL 不可用 | 降级到 Python 字典内存存储 |
| Milvus 不可用 | 降级到 jieba + BM25 内存关键词匹配 |
| DeepSeek API 不可用 | 返回预设的备用回复文案 |
| BGE 嵌入模型不可用 | 降级到纯关键词匹配 |

## 5. 安全设计

- 密码使用 bcrypt 加密存储（自动生成随机 salt）
- 用户名只能包含字母和数字
- 邮箱格式校验
- 消息长度限制 (1-2000 字符)
- CORS 跨域限制 (仅允许 localhost:8080)
- API 参数使用 Pydantic 模型自动校验
- 全局异常捕获，防止信息泄露
