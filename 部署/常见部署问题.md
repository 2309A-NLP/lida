## 1. 端口冲突

### 现象

启动时提示端口被占用：

```
ERROR:    [Errno 98] Address already in use
# 或
Error: That port is already in use.
```

### 排查步骤

```bash
# 查看端口占用情况
sudo lsof -i :8080
# 或
netstat -tlnp | grep 8080

# Windows PowerShell
netstat -ano | findstr :8080
```

### 解决方案

**方案 A：关闭占用端口的进程**

```bash
# 找到 PID 后强制终止
kill -9 <PID>

# Windows
taskkill /F /PID <PID>
```

**方案 B：更换启动端口**

```bash
python main.py --host 0.0.0.0 --port 9090
```

**方案 C：检查是否有其他 Python 进程残留**

```bash
# 查找残留的 Python 进程
ps aux | grep python
# 或
ps aux | grep uvicorn

# 全部终止
pkill -f uvicorn
pkill -f "python main.py"
```

### 预防

- 启动前使用 `lsof` 检查目标端口
- 使用 systemd 或 Docker 管理进程生命周期
- 避免使用 `Ctrl+Z` 暂停进程，应使用 `Ctrl+C`

## 2. MySQL 连接失败

### 现象

```
pymysql.err.OperationalError: (2003, "Can't connect to MySQL server on 'localhost:3306'")
# 或
pymysql.err.OperationalError: (1045, "Access denied for user 'root'@'localhost'")
# 或
pymysql.err.OperationalError: (1049, "Unknown database 'rag_chatbot'")
```

### 排查步骤

```bash
# 1. 检查 MySQL 是否运行
systemctl status mysql
# 或
docker ps | grep mysql

# 2. 检查端口是否监听
sudo lsof -i :3306
netstat -tlnp | grep 3306

# 3. 测试连接
mysql -h localhost -u root -p -e "SELECT 1;"
```

### 解决方案

**问题 1：MySQL 服务未启动**

```bash
# 启动 MySQL
sudo systemctl start mysql

# 或启动 Docker MySQL
docker start rag-mysql
```

**问题 2：用户名或密码错误**

```bash
# 重置 root 密码
sudo mysql
ALTER USER 'root'@'localhost' IDENTIFIED BY 'new_password';
FLUSH PRIVILEGES;

# 更新 .env 文件
MYSQL_USER=root
MYSQL_PASSWORD=new_password
```

**问题 3：数据库不存在**

```sql
-- 创建数据库
CREATE DATABASE IF NOT EXISTS rag_chatbot 
  CHARACTER SET utf8mb4 
  COLLATE utf8mb4_unicode_ci;
```

**问题 4：MySQL 连接被防火墙阻止**

```bash
# 检查防火墙规则
sudo ufw status
# 放行 3306 端口
sudo ufw allow from 127.0.0.1 to any port 3306
```

**问题 5：MySQL 绑定地址限制**

编辑 `/etc/mysql/mysql.conf.d/mysqld.cnf`：

```ini
bind-address = 0.0.0.0  # 允许所有连接（注意安全风险）
# 或
bind-address = 127.0.0.1  # 仅允许本地连接
```

**问题 6：Docker 中连接宿主机 MySQL**

在 Docker 容器中，使用 `host.docker.internal` 代替 `localhost`：

```ini
MYSQL_HOST=host.docker.internal
```

## 3. Redis 连接失败

### 现象

```
redis.exceptions.ConnectionError: Error -2 connecting to localhost:6379. Name or service not known.
# 或
redis.exceptions.ConnectionError: Error 111 connecting to localhost:6379. Connection refused.
# 或
redis.exceptions.ResponseError: NOAUTH Authentication required.
```

### 排查步骤

```bash
# 1. 检查 Redis 是否运行
systemctl status redis
# 或
docker ps | grep redis

# 2. 检查端口
sudo lsof -i :6379

# 3. 测试连接
redis-cli ping
# 期望返回: PONG
```

### 解决方案

**问题 1：Redis 未启动**

```bash
# 启动 Redis
sudo systemctl start redis
# 或
docker start rag-redis
```

**问题 2：Redis 需要密码认证**

检查 `.env` 中是否设置了 Redis 密码，或 Redis 配置中启用了 `requirepass`：

```bash
# 查看 Redis 配置
redis-cli CONFIG GET requirepass

# 如果设置了密码，需要在 .env 中添加
# REDIS_PASSWORD=your_password

# 如果不需要密码，可以禁用
redis-cli CONFIG SET requirepass ""
```

**问题 3：Redis 绑定地址**

编辑 `/etc/redis/redis.conf`：

```conf
# 允许所有连接
bind 0.0.0.0
# 或仅允许本地
bind 127.0.0.1
```

**问题 4：Docker 中 Redis 服务名解析**

Docker Compose 中，其他服务通过服务名 `redis` 访问：

```ini
REDIS_HOST=redis
```

## 4. API Key 配置错误

### 现象

```
httpx.RemoteProtocolError: 401 Unauthorized
# 或
json.decoder.JSONDecodeError: Expecting value: line 1 column 1
# 或
Model API call failed: Authentication failed
# 或
Model response is empty or invalid
```

### 排查步骤

```bash
# 1. 检查 .env 文件中的 API Key
cat .env | grep MODEL_API_KEY

# 2. 测试 API Key 是否有效
curl https://api.deepseek.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"Hello"}],"stream":false}'
```

### 解决方案

**问题 1：API Key 无效或过期**

- 登录 API 提供商控制台检查 Key 状态
- 重新生成 API Key 并更新 `.env`

**问题 2：API Endpoint 错误**

确认 `MODEL_ENDPOINT` 与 API Key 提供商匹配：

```ini
# DeepSeek
MODEL_ENDPOINT=https://api.deepseek.com/v1/chat/completions

# OpenAI
MODEL_ENDPOINT=https://api.openai.com/v1/chat/completions

# 其他兼容接口
MODEL_ENDPOINT=https://your-proxy-server.com/v1/chat/completions
```

**问题 3：API Key 格式问题**

- 检查 API Key 是否包含多余空格
- 检查 `.env` 文件中是否使用了引号（不需要引号）
- 检查 API Key 是否被截断（如 `sk-db1...72b8` 在显示时被截断）

```ini
# 正确格式
MODEL_API_KEY=sk-your-full-api-key-here-without-quotes
```

**问题 4：API 账户余额不足**

登录 API 提供商控制台检查账户余额和用量限额。

**问题 5：网络代理影响**

如使用代理，需确认代理配置是否正确：

```bash
# 检查代理环境变量
echo $HTTP_PROXY
echo $HTTPS_PROXY

# 临时禁用代理
unset HTTP_PROXY HTTPS_PROXY
```

## 5. Milvus 连接失败

### 现象

```
pymilvus.exceptions.MilvusException: <MilvusException: (code=1, message=can't connect to server)
# 或
pymilvus.exceptions.MilvusException: <MilvusException: (code=8, message=collection not found)
```

### 解决方案

**问题 1：Milvus 未启动**

```bash
# 启动 Milvus（需 etcd 和 minio）
docker compose up -d milvus etcd minio
```

**问题 2：Milvus 地址配置错误**

```ini
# Docker Compose 环境中
MILVUS_HOST=milvus
MILVUS_PORT=19530

# 本地部署
MILVUS_HOST=localhost
MILVUS_PORT=19530
```

**问题 3：集合未创建**

Milvus 需要先创建集合（collection），系统第一次启动时会自动创建。如未自动创建，可手动创建：

```python
from pymilvus import connections, Collection, FieldSchema, CollectionSchema, DataType

connections.connect(host="localhost", port=19530)

fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=1024),
    FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=65535),
]
schema = CollectionSchema(fields)
collection = Collection(name="rag_chatbot", schema=schema)
```

## 6. 依赖安装失败

### 现象

```
ERROR: Could not find a version that satisfies the requirement XXX
# 或
OSError: libcudart.so.11.0: cannot open shared object file
# 或
ERROR: Failed building wheel for sentence-transformers
```

### 解决方案

**问题 1：Python 版本不兼容**

```bash
# 检查 Python 版本
python --version
# 要求: 3.9 - 3.11

# 如果版本不对，安装正确版本
sudo apt install python3.10 python3.10-venv
```

**问题 2：CUDA 相关依赖缺失**

如果不需要 GPU 加速，可以忽略 CUDA 相关错误。如需 GPU：

```bash
# 检查 CUDA 版本
nvidia-smi
# 安装对应版本的 PyTorch
pip install torch --index-url https://download.pytorch.org/whl/cu118
```

**问题 3：使用国内镜像加速**

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**问题 4：sentence-transformers 安装失败**

```bash
# 确保先安装 PyTorch
pip install torch --index-url https://download.pytorch.org/whl/cpu
# 再安装 sentence-transformers
pip install sentence-transformers
```

**问题 5：编译依赖缺失（Linux）**

```bash
# Ubuntu/Debian
sudo apt install build-essential python3-dev

# CentOS/RHEL
sudo yum install gcc python3-devel
```

## 7. 虚拟环境问题

### 现象

```
ModuleNotFoundError: No module named 'fastapi'
# 或
-bash: pip: command not found
```

### 解决方案

**问题 1：未激活虚拟环境**

```bash
# Linux/macOS
source venv/bin/activate

# Windows
venv\Scripts\activate

# 确认已激活（命令行前缀应有 (venv)）
which python
```

**问题 2：pip 未安装**

```bash
# 安装 pip
python -m ensurepip --upgrade

# 或
curl https://bootstrap.pypa.io/get-pip.py | python
```

**问题 3：pip 版本过旧**

```bash
pip install --upgrade pip
```

**问题 4：虚拟环境损坏**

重建虚拟环境：

```bash
# 删除旧的
rm -rf venv

# 创建新的
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## 8. Docker 相关问题

### 8.1 容器启动失败

**查看日志：**

```bash
docker logs rag_backend1
docker compose logs backend1
```

**常见原因：**

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `port is already allocated` | 端口冲突 | 停止占用端口的容器，或修改端口映射 |
| `Cannot connect to the Docker daemon` | Docker 未运行 | `sudo systemctl start docker` |
| ` permission denied` | 权限不足 | 将用户加入 docker 组：`sudo usermod -aG docker $USER` |
| `No such image` | 镜像未构建 | 先执行 `docker compose build` |

### 8.2 Docker 网络问题

```bash
# 检查网络连通性
docker exec rag_backend1 ping redis
docker exec rag_backend1 ping milvus

# 如果 ping 不通，检查 Docker 网络
docker network ls
docker network inspect rag_rag_network
```

### 8.3 Docker 磁盘空间不足

```bash
# 查看磁盘使用
docker system df

# 清理未使用的资源
docker system prune -a

# 清理卷
docker volume prune
```

### 8.4 查看资源使用

```bash
# 查看所有容器资源
docker stats

# 限制容器资源（修改 docker-compose.yml）
backend1:
  deploy:
    resources:
      limits:
        cpus: '2'
        memory: 4G
      reservations:
        cpus: '1'
        memory: 2G
```

## 9. Nginx 相关问题

### 9.1 502 Bad Gateway

**原因：** Nginx 无法连接到后端服务。

**排查步骤：**

```bash
# 1. 检查后端服务是否运行
docker ps | grep backend
curl http://localhost:8081/health

# 2. 检查 Nginx 日志
tail -f /var/log/nginx/rag-error.log

# 3. 检查 upstream 配置
# 确保 upstream 中的服务器地址和端口正确
```

**解决方案：**

- 启动后端服务：`docker compose up -d backend1 backend2 backend3`
- 检查 `nginx.conf` 中的 `upstream` 服务器地址
- 检查后端服务端口是否被占用

### 9.2 504 Gateway Timeout

**原因：** 后端服务响应超时。

**解决方案：**

```nginx
# 增大超时时间
proxy_connect_timeout 60s;
proxy_read_timeout 120s;
proxy_send_timeout 120s;
```

### 9.3 413 Request Entity Too Large

**原因：** 上传文件大小超过限制。

**解决方案：**

```nginx
client_max_body_size 50M;  # 根据需要调整
```

### 9.4 配置重载失败

```bash
# 检查配置语法
sudo nginx -t

# 常见错误：
# - 缺少分号
# - 花括号不匹配
# - 文件路径错误

# 使用检查结果修正配置后重试
sudo nginx -s reload
```

## 10. 启动报错汇总

### 10.1 模块导入错误

```
ModuleNotFoundError: No module named 'xxx'
```

| 缺少的模块 | 安装命令 | 备注 |
|-----------|---------|------|
| fastapi | `pip install fastapi` | Web 框架 |
| uvicorn | `pip install uvicorn` | ASGI 服务器 |
| pymysql | `pip install pymysql` | MySQL 驱动 |
| redis | `pip install redis` | Redis 客户端 |
| pymilvus | `pip install pymilvus` | Milvus 客户端 |
| langchain | `pip install langchain` | LLM 框架 |
| sentence-transformers | `pip install sentence-transformers` | 嵌入模型 |

### 10.2 .env 文件未找到

```
ValueError: Model API key not configured
```

确保 `.env` 文件存在于项目根目录，且包含必要配置项。

### 10.3 配置文件错误

```
pydantic_core._pydantic_core.ValidationError:
```

检查 `.env` 中的配置项格式是否正确，特别是：
- 端口号是否为整数
- 布尔值是否为 `true`/`false`（小写）
- URL 格式是否正确

### 10.4 SQLAlchemy 连接池耗尽

```
sqlalchemy.exc.TimeoutError: QueuePool limit of size 5 overflow 10 reached
```

在配置中增大连接池大小：

```python
# config/settings.py
DATABASE_POOL_SIZE = 20
DATABASE_MAX_OVERFLOW = 40
```

### 10.5 内存不足

```
Killed  (进程被 OOM Killer 终止)
```

- 增大系统内存
- 限制模型使用的内存
- 使用 `USE_LOCAL_EMBEDDING=false` 避免加载本地嵌入模型

## 通用排查流程

遇到问题时，按照以下流程排查：

```
1. 检查服务是否运行
   └── docker ps / systemctl status / ps aux

2. 检查日志
   └── docker logs / tail -f logs/*.log / journalctl

3. 检查配置文件
   └── .env 中的连接参数是否正确

4. 检查网络连通性
   └── ping / curl / telnet 测试各服务端口

5. 检查资源使用
   └── free -h / df -h / docker stats

6. 搜索错误信息
   └── 复制完整错误信息搜索解决方案
```

如果以上步骤无法解决问题，请提供完整的错误日志和配置文件（注意隐藏敏感信息）。
