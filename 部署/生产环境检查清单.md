# 生产环境检查清单

本文档为生产环境部署 RAG 多角色智能聊天机器人系统提供全面的检查清单，涵盖安全、性能、监控和日志管理四个方面。

---

## 一、安全检查

### 1.1 环境变量与密钥

- [ ] `.env` 文件中的 `MODEL_API_KEY` 已设置为真实密钥
- [ ] `MYSQL_PASSWORD` 已设置为强密码（至少 16 位，含大小写字母、数字和特殊字符）
- [ ] `.env` 文件不应提交到 Git 仓库（已在 `.gitignore` 中排除）
- [ ] 生产环境 `DEBUG = False`
- [ ] API Key 有访问权限控制和额度限制

### 1.2 网络与防火墙

- [ ] 数据库端口（3306, 6379, 19530）未暴露到公网
- [ ] 仅 Nginx 端口（80/443）对外暴露
- [ ] 后端服务端口（8080-8083）仅限内网访问
- [ ] 已配置防火墙规则（iptables / ufw / 云安全组）
- [ ] SSH 端口已修改（非默认 22）或使用密钥登录

### 1.3 Nginx 安全

- [ ] `server_tokens off` 已启用（隐藏 Nginx 版本号）
- [ ] 已限制请求方法（仅允许 GET, POST, HEAD）
- [ ] 已配置安全响应头（X-Frame-Options, X-Content-Type-Options 等）
- [ ] 已配置请求频率限制（rate limiting）
- [ ] 已配置连接数限制
- [ ] HTTPS 已启用（使用 Let's Encrypt 免费证书）
- [ ] HTTP 自动重定向到 HTTPS
- [ ] SSL 配置评为 A 级（可通过 SSL Labs 测试）

### 1.4 应用安全

- [ ] CORS 已配置为具体的允许域名（非 `*`）
- [ ] 用户输入已做清理和校验
- [ ] API 端点有认证/授权机制
- [ ] 上传文件大小已限制（`client_max_body_size`）
- [ ] 敏感信息不在日志中记录

### 1.5 数据安全

- [ ] MySQL 数据库定期备份（建议每日）
- [ ] Redis 启用密码保护（`requirepass`）
- [ ] Milvus 数据有备份策略
- [ ] 备份文件加密存储
- [ ] 数据库连接使用最小权限账户

## 二、性能检查

### 2.1 系统资源

- [ ] CPU 核数满足需求（推荐 8 核以上）
- [ ] 内存充足（推荐 16 GB 以上）
- [ ] 磁盘 IOPS 足够（推荐 SSD）
- [ ] 网络带宽充足
- [ ] 检查 `ulimit -n`（文件描述符限制，推荐 65535+）

### 2.2 应用配置

- [ ] Uvicorn worker 数量配置合理（通常为 CPU 核数 x 2 + 1）
- [ ] 如使用 Gunicorn + Uvicorn，配置 worker 数量

修改 `main.py` 的启动方式（生产环境）：

```bash
# 使用 gunicorn 多 worker 启动
pip install gunicorn
gunicorn main:app \
  --worker-class uvicorn.workers.UvicornWorker \
  --workers 4 \
  --bind 0.0.0.0:8080 \
  --timeout 120 \
  --keep-alive 5 \
  --max-requests 1000 \
  --max-requests-jitter 100
```

### 2.3 Nginx 性能优化

- [ ] `worker_processes auto`（自动匹配 CPU 核数）
- [ ] `worker_connections` 已调大（推荐 4096+）
- [ ] Gzip 压缩已启用（减少传输量 60-70%）
- [ ] 静态文件缓存已配置（7 天有效期）
- [ ] `sendfile`, `tcp_nopush`, `tcp_nodelay` 已启用
- [ ] `keepalive_timeout` 和 `keepalive_requests` 已配置
- [ ] upstream `keepalive` 连接数已配置（32+）

### 2.4 数据库性能

- [ ] MySQL 已配置合适的 `innodb_buffer_pool_size`（建议物理内存的 60-70%）
- [ ] Redis `maxmemory` 已设置（建议不超过物理内存的 70%）
- [ ] 数据库连接池大小已优化
- [ ] 慢查询日志已开启并分析
- [ ] 数据表索引已建立

### 2.5 模型性能

- [ ] 在线 API 模式：确认 API 调用频率和并发限制
- [ ] 本地模型模式：GPU 资源已正确配置
- [ ] 嵌入模型缓存已启用（避免重复加载）
- [ ] 重排序模型使用策略已优化（仅对 Top-K 结果重排）

### 2.6 压力测试

- [ ] 已进行基础 QPS 测试（可使用 `tests/qps_test.py`）
- [ ] 已模拟并发用户测试
- [ ] 已进行长时间稳定性测试（至少 24 小时）
- [ ] 已确定系统瓶颈（CPU、内存、IO、网络）

## 三、监控配置

### 3.1 应用健康检查

- [ ] `/health` 端点正常工作
- [ ] Docker HEALTHCHECK 已配置并正常运行
- [ ] 健康检查失败时自动重启
- [ ] Nginx 对后端进行被动健康检查（请求失败自动摘除）

### 3.2 系统监控

推荐使用以下监控方案之一：

**方案 A：Prometheus + Grafana（推荐）**

```yaml
# docker-compose 添加监控服务
prometheus:
  image: prom/prometheus
  volumes:
    - ./prometheus.yml:/etc/prometheus/prometheus.yml
  ports:
    - "9090:9090"

grafana:
  image: grafana/grafana
  ports:
    - "3000:3000"
  depends_on:
    - prometheus
```

- [ ] Prometheus 已部署并采集指标
- [ ] Grafana 面板已配置（系统资源、应用指标、API 调用量）
- [ ] 告警规则已设置（CPU > 80%、内存 > 80%、磁盘 > 85%）

**方案 B：云服务监控**

- [ ] 云平台基础监控已开启（CPU、内存、磁盘、网络）
- [ ] 云平台告警已配置

**方案 C：简单监控脚本**

- [ ] 定时 curl 健康检查脚本
- [ ] 失败时发送通知（邮件/微信/短信）

### 3.3 应用指标监控

- [ ] API 请求总数和 QPS
- [ ] API 响应时间（P50, P90, P99）
- [ ] API 错误率
- [ ] 模型调用次数和耗时
- [ ] 向量检索耗时
- [ ] 数据库连接池使用率

### 3.4 告警通知

- [ ] 服务宕机告警
- [ ] API 错误率超过阈值告警（如 > 5%）
- [ ] 响应时间超过阈值告警（如 P99 > 3s）
- [ ] 磁盘空间不足告警
- [ ] SSL 证书即将过期告警（提前 30 天）

## 四、日志管理

### 4.1 日志配置

- [ ] 日志级别已设置为 `INFO` 或 `WARNING`（生产环境不推荐 `DEBUG`）
- [ ] 日志格式包含：时间戳、日志级别、模块名、请求 ID
- [ ] 日志文件按日期滚动（避免单文件过大）
- [ ] 日志保留策略已配置（建议保留 30 天）

推荐日志配置（修改 `config/settings.py` 或 `utils/logger.py`）：

```python
import logging
from logging.handlers import TimedRotatingFileHandler

handler = TimedRotatingFileHandler(
    "logs/app.log",
    when="midnight",
    interval=1,
    backupCount=30  # 保留 30 天
)
handler.setFormatter(logging.Formatter(
    "%(asctime)s - %(name)s - %(levelname)s - %(message)s"
))
```

### 4.2 Nginx 日志

- [ ] 访问日志格式包含响应时间（已配置 `$request_time`）
- [ ] 错误日志级别为 `warn`
- [ ] 日志按天切割（使用 `logrotate`）

`/etc/logrotate.d/nginx` 配置示例：

```
/var/log/nginx/*.log {
    daily
    missingok
    rotate 30
    compress
    delaycompress
    notifempty
    create 640 nginx adm
    sharedscripts
    postrotate
        [ -f /var/run/nginx.pid ] && kill -USR1 `cat /var/run/nginx.pid`
    endscript
}
```

### 4.3 集中日志管理（可选）

推荐方案：

| 方案 | 适用场景 | 复杂度 |
|------|---------|--------|
| ELK Stack | 大规模部署 | 高 |
| Loki + Grafana | 与 Prometheus 配合 | 中 |
| 云日志服务 | 云原生部署 | 低 |
| 本地文件 + grep | 小规模部署 | 低 |

### 4.4 Docker 日志

- [ ] Docker 日志驱动已配置（建议 `json-file` 或 `loki`）
- [ ] 日志大小限制已设置（避免占满磁盘）

在 `/etc/docker/daemon.json` 中配置：

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

## 启动命令参考

```bash
# 单体部署（生产模式）
python main.py --host 0.0.0.0 --port 8080 --no-reload

# Docker Compose 部署
docker compose up -d --build

# Gunicorn 部署（推荐生产）
gunicorn main:app \
  --worker-class uvicorn.workers.UvicornWorker \
  --workers $(nproc) \
  --bind 0.0.0.0:8080 \
  --timeout 120 \
  --max-requests 10000 \
  --max-requests-jitter 1000 \
  --access-logfile logs/access.log \
  --error-logfile logs/error.log
```
